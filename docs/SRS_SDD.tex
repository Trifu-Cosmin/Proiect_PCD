\section{Introducere}

Acest document contine specificatia cerintelor software si descrierea de proiectare pentru aplicatia T17 - Analiza Semantica Cod Sursa. Proiectul este realizat pentru disciplina Programare Concurenta si Distribuita si are ca scop implementarea unei aplicatii client-server care permite incarcarea unor fisiere sursa C, analiza lor cu ajutorul bibliotecii libclang si generarea unor rapoarte text.

Aplicatia foloseste comunicare prin socket-uri, procese multiple, autentificare, transfer de fisiere, generare de rapoarte, operatii de administrare si monitorizare a directorului de rapoarte.

\section{Scopul proiectului}

Scopul proiectului este realizarea unui sistem distribuit simplu, dar complet functional, care permite:

\begin{itemize}
    \item incarcarea unui fisier sursa C de la client catre server;
    \item analiza fisierului folosind libclang;
    \item generarea unui raport cu informatii despre cod;
    \item descarcarea raportului de catre client;
    \item administrarea serverului printr-un client separat;
    \item folosirea socket-urilor INET si UNIX;
    \item folosirea mecanismelor \texttt{fork()}, \texttt{exec()}, \texttt{pipe()}, \texttt{select()} si \texttt{inotify}.
\end{itemize}

\section{Domeniul aplicatiei}

Aplicatia este destinata analizei statice a fisierelor C. Sistemul nu executa codul primit, ci il parseaza si extrage informatii relevante despre structura si posibile probleme din cod.

Analiza include:

\begin{itemize}
    \item numar de functii;
    \item numar de variabile;
    \item numar de instructiuni \texttt{if};
    \item numar de instructiuni \texttt{for};
    \item numar de instructiuni \texttt{while};
    \item diagnostice generate de libclang;
    \item mesaje de warning sau error pentru cod problematic.
\end{itemize}

\section{Descriere generala}

Sistemul are o arhitectura client-server. Clientii normali comunica cu serverul printr-un socket INET TCP pe adresa \texttt{127.0.0.1:8080}. Clientul admin comunica separat printr-un socket UNIX local, folosind calea \texttt{/tmp/t17\_admin.sock}.

Serverul asteapta conexiuni folosind \texttt{select()} pentru a monitoriza simultan socket-ul TCP si socket-ul UNIX. Pentru fiecare conexiune acceptata, serverul creeaza un proces copil cu \texttt{fork()}, iar procesul copil trateaza clientul respectiv.

\begin{enumerate}[label=CF\arabic*., resume]
    \item Serverul trebuie sa porneasca pe socket INET TCP la adresa \texttt{127.0.0.1:8080}.

    \item Serverul trebuie sa accepte comenzi de upload si download pentru clientii normali.
    \item Serverul trebuie sa execute analyzer-ul folosind \texttt{fork()}, \texttt{exec()} si \texttt{pipe()}.
    \item Serverul trebuie sa scrie loguri in \texttt{logs/server.log}.
    \item Serverul trebuie sa mentina statistici in \texttt{logs/stats.txt}.

\section{Cerinte nefunctionale}

\begin{enumerate}[label=CNF\arabic*.]

\section{Arhitectura sistemului}

Arhitectura generala este urmatoarea:

\begin{lstlisting}[style=code]
Client C normal      \
                     -> INET TCP 127.0.0.1:8080 -> Server -> Analyzer -> Report
Client Python        /

Admin Client C       -> UNIX socket /tmp/t17_admin.sock -> Server

Serverul are doua puncte de intrare:

\begin{itemize}

\section{Componente software}

\subsection{\texttt{src/analyzer.c}}

Componenta \texttt{analyzer.c} foloseste libclang pentru a analiza fisiere C. Aceasta componenta primeste fisierul prin argumente de linie de comanda si afiseaza rezultatul analizei la \texttt{stdout}. Serverul captureaza acest output prin pipe.

\subsection{\texttt{src/server.c}}

Componenta principala a sistemului. Serverul:

\begin{itemize}
    \item creeaza socket-ul INET pentru clientii normali;
    \item creeaza socket-ul UNIX pentru admin;
    \item foloseste \texttt{select()} pentru a astepta conexiuni;
    \item foloseste \texttt{fork()} pentru clienti;
    \item autentifica utilizatorii;
    \item primeste fisiere;
    \item ruleaza analyzer-ul;
    \item salveaza rapoarte;
    \item gestioneaza comenzi admin.
\end{itemize}

\subsection{\texttt{src/client.c}}

Clientul C normal permite upload-ul fisierelor si descarcarea rapoartelor. Acesta comunica prin TCP cu serverul.

\subsection{\texttt{src/admin\_client.c}}

Clientul admin comunica prin socket UNIX si permite operatii de administrare:

\begin{itemize}
    \item \texttt{STATS};
    \item \texttt{LOGS};
    \item \texttt{LIST\_UPLOADS};
    \item \texttt{LIST\_REPORTS};
    \item \texttt{SERVER\_STATUS};
    \item \texttt{CLEAR\_LOGS};
    \item \texttt{DELETE\_REPORT};
    \item \texttt{LIST\_USERS};
    \item \texttt{JOBS}.
\end{itemize}

\subsection{\texttt{python\_client/client.py}}

Clientul Python este o alternativa la clientul C si demonstreaza interoperabilitatea protocolului TCP.

\subsection{\texttt{src/watch\_reports.c}}

Program separat care foloseste \texttt{inotify} pentru monitorizarea directorului \texttt{reports/}. Acesta afiseaza evenimente atunci cand rapoartele sunt create, modificate sau sterse.

\section{Protocol de comunicare}

Protocolul este text-based. Fiecare client trimite mai intai o comanda de login:

\begin{lstlisting}[style=code]
LOGIN <username> <password>
\end{lstlisting}

Serverul raspunde cu:

\begin{lstlisting}[style=code]
RESULT <size>
OK role=<role>
\end{lstlisting}

Clientii normali pot folosi:

\begin{lstlisting}[style=code]
UPLOAD <filename> <size>
DOWNLOAD_REPORT <report_name>
QUIT
\end{lstlisting}

Clientul admin poate folosi:

\begin{lstlisting}[style=code]
STATS
LOGS
LIST_UPLOADS
LIST_REPORTS
SERVER_STATUS
CLEAR_LOGS
DELETE_REPORT <report_name>
LIST_USERS
JOBS
QUIT
\end{lstlisting}

\section{Fluxuri de executie}

\subsection{Upload si analiza fisier}

\begin{enumerate}
    \item Clientul se conecteaza la server prin TCP.
    \item Clientul trimite comanda \texttt{LOGIN}.
    \item Serverul verifica utilizatorul in \texttt{config/users.cfg}.
    \item Clientul trimite comanda \texttt{UPLOAD}.
    \item Serverul salveaza fisierul in \texttt{uploads/}.
    \item Serverul scrie jobul cu status \texttt{QUEUED}.
    \item Serverul ruleaza analyzer-ul cu \texttt{fork()}, \texttt{exec()} si \texttt{pipe()}.
    \item Serverul scrie status \texttt{RUNNING}, apoi \texttt{DONE} sau \texttt{FAILED}.
    \item Serverul salveaza raportul in \texttt{reports/}.
    \item Serverul trimite rezultatul catre client.
\end{enumerate}

\subsection{Administrare server}

\begin{enumerate}
    \item Admin clientul se conecteaza la \texttt{/tmp/t17\_admin.sock}.
    \item Admin clientul trimite login cu rol de admin.
    \item Serverul verifica rolul.
    \item Adminul trimite una dintre comenzile suportate.
    \item Serverul intoarce rezultatul.
\end{enumerate}

\subsection{Monitorizare rapoarte}

\begin{enumerate}
    \item Utilizatorul porneste programul \texttt{watch\_reports}.
    \item Programul adauga un watch cu \texttt{inotify\_add\_watch()} pe \texttt{reports/}.
    \item Cand apare un raport nou, programul afiseaza evenimentul.
\end{enumerate}

\section{Limitari curente}

Aplicatia are urmatoarele limitari:

\begin{itemize}
    \item analiza este concentrata pe fisiere C;
    \item protocolul este simplu, text-based;
    \item REST este documentat prin OpenAPI, dar implementarea principala este socket-based;
    \item job tracking-ul este salvat in fisier text, nu intr-o baza de date;
    \item serverul este destinat pentru testare locala.
\end{itemize}

\section{Directii viitoare}

Directii posibile de dezvoltare:

\begin{itemize}
    \item implementarea unui REST API real;
    \item adaugarea unei cozi asincrone reale pentru joburi;
    \item analiza mai avansata a codului;
    \item suport mai bun pentru fisiere C++;
    \item salvarea rezultatelor intr-o baza de date;
    \item interfata grafica pentru vizualizarea rapoartelor.
\end{itemize}

\section{Concluzie}

Proiectul implementeaza o aplicatie client-server functionala pentru analiza semantica a codului sursa C. Sistemul foloseste socket-uri INET pentru clientii normali, socket UNIX pentru administrare, \texttt{select()} pentru monitorizarea mai multor socket-uri, \texttt{fork()} pentru concurenta, \texttt{exec()} si \texttt{pipe()} pentru rularea analyzer-ului, precum si \texttt{inotify} pentru monitorizarea rapoartelor generate.

Prin aceste functionalitati, proiectul acopera cerinte importante din zona de programare concurenta si distribuita.
