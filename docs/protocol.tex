\section{Introducere}

Acest document descrie protocolul de comunicare folosit in proiectul T17 - Analiza Semantica Cod Sursa.

Protocolul este text-based si ruleaza peste doua tipuri de socket-uri:

\begin{itemize}
    \item socket INET TCP pentru clientii normali;
    \item socket UNIX pentru clientul admin.
\end{itemize}

Clientii normali comunica prin:

\begin{lstlisting}[style=code]
127.0.0.1:8080
\end{lstlisting}

Clientul admin comunica prin:

\begin{lstlisting}[style=code]
/tmp/t17_admin.sock
\end{lstlisting}

\section{Model de comunicare}

Fiecare conexiune incepe obligatoriu cu o comanda de autentificare:

\begin{lstlisting}[style=code]
LOGIN <username> <password>
\end{lstlisting}

Dupa autentificare, clientul trimite o singura comanda principala catre server. Serverul proceseaza comanda si raspunde.

Serverul creeaza cate un proces copil pentru fiecare conexiune acceptata. Socket-urile principale sunt monitorizate cu \texttt{select()}.

\section{Format raspunsuri}

\subsection{Raspuns text}

Pentru raspunsuri text, serverul foloseste formatul:

\begin{lstlisting}[style=code]
RESULT <size>
<body>
\end{lstlisting}

Unde:

\begin{itemize}
    \item \texttt{size} este dimensiunea corpului raspunsului in bytes;
    \item \texttt{body} este textul propriu-zis.
\end{itemize}

Exemplu:

\begin{lstlisting}[style=code]
RESULT 14
OK role=admin
\end{lstlisting}

\subsection{Raspuns fisier}

Pentru download de raport, serverul foloseste formatul:

\begin{lstlisting}[style=code]
FILE <filename> <size>
<file_content>
\end{lstlisting}

Unde:

\begin{itemize}
    \item \texttt{filename} este numele raportului;
    \item \texttt{size} este dimensiunea fisierului in bytes;
    \item \texttt{file\_content} este continutul binar/text al fisierului.
\end{itemize}

\section{Autentificare}

Comanda de autentificare:

\begin{lstlisting}[style=code]
LOGIN <username> <password>
\end{lstlisting}

Exemplu pentru user normal:

\begin{lstlisting}[style=code]
LOGIN user1 pass1
\end{lstlisting}

Exemplu pentru admin:

\begin{lstlisting}[style=code]
LOGIN admin admin123
\end{lstlisting}

Raspuns pentru autentificare reusita:

\begin{lstlisting}[style=code]
RESULT <size>
OK role=<role>
\end{lstlisting}

Raspuns pentru autentificare esuata:

\begin{lstlisting}[style=code]
RESULT <size>
ERROR: invalid credentials
\end{lstlisting}

Utilizatorii sunt cititi din:

\begin{lstlisting}[style=code]
config/users.cfg
\end{lstlisting}

Format fisier:

\begin{lstlisting}[style=code]
username:password:role
\end{lstlisting}

\section{Comenzi pentru client normal}

Clientul normal foloseste socket INET TCP.

\subsection{UPLOAD}

Comanda:

\begin{lstlisting}[style=code]
UPLOAD <filename> <size>
<file_content>
\end{lstlisting}

Exemplu:

\begin{lstlisting}[style=code]
UPLOAD sample.c 582
\end{lstlisting}

Serverul salveaza fisierul in:

\begin{lstlisting}[style=code]
uploads/
\end{lstlisting}

Apoi ruleaza analyzer-ul si trimite rezultatul inapoi ca raspuns \texttt{RESULT}.

\subsection{DOWNLOAD\_REPORT}

Comanda:

\begin{lstlisting}[style=code]
DOWNLOAD_REPORT <report_name>
\end{lstlisting}

Exemplu:

\begin{lstlisting}[style=code]
DOWNLOAD_REPORT sample_report.txt
\end{lstlisting}

Serverul cauta raportul in:

\begin{lstlisting}[style=code]
reports/
\end{lstlisting}

Daca exista, raspunde cu:

\begin{lstlisting}[style=code]
FILE sample_report.txt <size>
<content>
\end{lstlisting}

\subsection{QUIT}

Comanda:

\begin{lstlisting}[style=code]
QUIT
\end{lstlisting}

Raspuns:

\begin{lstlisting}[style=code]
RESULT <size>
BYE
\end{lstlisting}

\section{Comenzi pentru admin}

Clientul admin foloseste socket UNIX:

\begin{lstlisting}[style=code]
/tmp/t17_admin.sock
\end{lstlisting}

Comenzile admin sunt acceptate doar daca:

\begin{itemize}
    \item conexiunea vine prin socket UNIX;
    \item rolul utilizatorului este \texttt{admin}.
\end{itemize}

\subsection{STATS}

Comanda:

\begin{lstlisting}[style=code]
STATS
\end{lstlisting}

Descriere: afiseaza statistici simple despre server.

Exemplu raspuns:

\begin{lstlisting}[style=code]
Server status: running
Analyzed files: 18
Last file: sample.c
\end{lstlisting}

\subsection{LOGS}

Comanda:

\begin{lstlisting}[style=code]
LOGS
\end{lstlisting}

Descriere: afiseaza continutul fisierului:

\begin{lstlisting}[style=code]
logs/server.log
\end{lstlisting}

\subsection{LIST\_UPLOADS}

Comanda:

\begin{lstlisting}[style=code]
LIST_UPLOADS
\end{lstlisting}

Descriere: listeaza fisierele din directorul:

\begin{lstlisting}[style=code]
uploads/
\end{lstlisting}

\subsection{LIST\_REPORTS}

Comanda:

\begin{lstlisting}[style=code]
LIST_REPORTS
\end{lstlisting}

Descriere: listeaza rapoartele din directorul:

\begin{lstlisting}[style=code]
reports/
\end{lstlisting}

\subsection{SERVER\_STATUS}

Comanda:

\begin{lstlisting}[style=code]
SERVER_STATUS
\end{lstlisting}

Descriere: afiseaza informatii despre configuratia serverului.

Exemplu raspuns:

\begin{lstlisting}[style=code]
Server status: running
INET socket: 127.0.0.1:8080
UNIX admin socket: /tmp/t17_admin.sock
Connection model: select() + fork() per client
Normal clients: C client and Python client over INET TCP
Admin client: UNIX domain socket
\end{lstlisting}

\subsection{CLEAR\_LOGS}

Comanda:

\begin{lstlisting}[style=code]
CLEAR_LOGS
\end{lstlisting}

Descriere: goleste fisierul:

\begin{lstlisting}[style=code]
logs/server.log
\end{lstlisting}

\subsection{DELETE\_REPORT}

Comanda:

\begin{lstlisting}[style=code]
DELETE_REPORT <report_name>
\end{lstlisting}

Exemplu:

\begin{lstlisting}[style=code]
DELETE_REPORT sample_report.txt
\end{lstlisting}

Descriere: sterge raportul specificat din directorul \texttt{reports/}.

\subsection{LIST\_USERS}

Comanda:

\begin{lstlisting}[style=code]
LIST_USERS
\end{lstlisting}

Descriere: listeaza utilizatorii configurati, fara a afisa parolele.

Exemplu raspuns:

\begin{lstlisting}[style=code]
Configured users:
- user1 : user
- admin : admin
\end{lstlisting}

\subsection{JOBS}

Comanda:

\begin{lstlisting}[style=code]
JOBS
\end{lstlisting}

Descriere: afiseaza istoricul joburilor de analiza din:

\begin{lstlisting}[style=code]
logs/jobs.log
\end{lstlisting}

Exemplu raspuns:

\begin{lstlisting}[style=code]
[2026-06-12 12:17:08] sample.c QUEUED
[2026-06-12 12:17:08] sample.c RUNNING
[2026-06-12 12:17:09] sample.c DONE
\end{lstlisting}

\section{Coduri de eroare}

Erorile sunt trimise tot ca raspuns \texttt{RESULT}.

Exemple:

\begin{lstlisting}[style=code]
ERROR: login required
ERROR: invalid credentials
ERROR: admin commands require UNIX socket
ERROR: admin permission required
ERROR: unknown command
ERROR: analyzer failed
ERROR: cannot delete report
ERROR: report file not found
\end{lstlisting}

\section{Exemple de fluxuri}

\subsection{Flux upload}

\begin{lstlisting}[style=code]
Client -> Server:
LOGIN user1 pass1

Server -> Client:
RESULT 13
OK role=user

Client -> Server:
UPLOAD sample.c 582
<file bytes>

Server -> Client:
RESULT <size>
<analysis result>
\end{lstlisting}

\subsection{Flux admin}

\begin{lstlisting}[style=code]
Admin -> Server:
LOGIN admin admin123

Server -> Admin:
RESULT 14
OK role=admin

Admin -> Server:
JOBS

Server -> Admin:
RESULT <size>
[2026-06-12 12:17:08] sample.c QUEUED
[2026-06-12 12:17:08] sample.c RUNNING
[2026-06-12 12:17:09] sample.c DONE
\end{lstlisting}

\section{Concluzie}

Protocolul este simplu, text-based si usor de testat. Clientii normali folosesc comunicare INET TCP, iar administrarea se face separat prin socket UNIX. Aceasta separare face proiectul mai clar si permite demonstrarea mai multor mecanisme de programare concurenta si distribuita.
